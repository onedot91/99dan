# 5·10문제 선택 및 별도 명예의 전당

2026-10-03. 로컬 앱의 예비 번호와 격리 PostgreSQL만 사용했다. 운영 SQL·Edge 배포는 승인 대기다.

## 동작
- 홈 선택지 1분/2분/3분/5문제/10문제는 같은 폭이며 선택한 문제 수를 시작 버튼에 표시한다.
- 10문제 출제 비중은 下 4/4/2, 中 2/4/4, 上 0/2/8이다. 난이도 선택은 교사에게만 있고 학생은 문제 수만 선택한다.
- 진행·종료·결과·재시작은 5/10을 따른다. 기존 5문제 저장 기록을 유지하며 10문제 완료 기록도 검증 후 복원한다. 중도 나가기에서는 재개하지 않는다.
- 명예의 전당은 두 자리 수 탭 아래 5/10문제별 순위를 분리한다. 난이도는 합산하며 문제당 200점·오답 −30점·칸별 시간 최대 −4점을 유지한다. 최대 점수는 1,000/2,000이다.

## UI 관찰
- 320×568에서 다섯 홈 선택지가 각 약 51px×44px로 보이고 줄바꿈·가로 넘침이 없다. 긴 10문제 문구가 맞도록 모바일 글자 크기를 조정했다.
- 10문제의 5번째 완료 후 6번째 문항으로 진행했고 두 번의 전체 10문제 풀이 후 각각 2,000점을 표시했다.
- 320×568과 375×667에서 헤더 10칸과 점수, 모든 키패드 버튼이 화면 안에 보였다. 768×650에서 헤더 나가기의 줄바꿈을 발견해 10칸·점수의 크기를 줄였고 이후 나가기 버튼 높이 48px을 확인했다.
- 320×568의 결과 목록은 높이 200px/전체 380px 스크롤이다. End 키 후 scrollTop 180과 10번째 식 표시를 확인했다. 하단 재시작 버튼 끝 y=556.79로 화면 안에 보인다.
- 완료 화면에서 명예의 전당을 열면 10문제가 선택된다. 5/10 전환이 동작하며 320px에서 두 버튼은 각각 142px로 같은 폭이다. 상단 구구단/두 자리 수도 동일한 폭이다.
- 새 세트에서 문항이 바뀌는 것을 확인했다. 운영 학생 풀이·가상 순위는 생성하지 않았다.
- `새 10문제 풀기`가 다시 10문제로 시작하고, 나간 뒤 이어서 풀기가 없는 것을 확인했다. 마지막 실행의 브라우저 warn/error는 없었으며 테스트 탭을 닫고 뷰포트를 복원했다.

## 검증
- Node 단위/API 테스트 34/34 통과.
- `npm run build`와 `git diff --check` 통과.
- 격리 DB 18개 5/10문제 세트의 JS/SQL 채점 일치, 정답 누락·5문제에서 조기 완료·ID 소유자 변경·count 변경 재시도 거부, 순위 분리, RPC 공개 역할 차단 통과.
- 기존 5문제 회귀: 처음 복제 DB의 과거 가상 순위 때문에 실패. 새 빈 DB에서 같은 검사를 재실행해 8,100개 계산·정답 순서·점수·순위·재시도·초기화·권한 검사가 통과했다.
- 빈칸별 시간 21가지 및 교사 추천 8,100개 분류 회귀 통과.
- strict Edge TypeScript 검사 통과. strict가 없는 검사에서 기존 unknown/null 좁히기 오류가 나타났으나 프로젝트와 같은 strict 설정으로 검사했을 때 통과했으며 관련 코드 변경은 하지 않았다.
- 실제 학교 기기와 운영 10문제 API는 아직 검증하지 않았다. 운영은 SQL·Edge 승인 후 검증한다.
