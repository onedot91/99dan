## 기준

두 자리 수 새 도전만 cellScoring:true로 합의한다. 문제당 200점을 입력 칸 수로 분배하고 각 칸의 기본 점수는 floor((step+1)×200/칸수)−floor(step×200/칸수)로 계산한다. 입력 순서가 자유로운 빈칸 문항도 칸 인덱스에 따라 같은 배점을 사용한다.

시간은 활성화된 칸 기준으로 측정한다. 2초까지 기본 배점의 100%, 이후 1초 구간마다 5%포인트를 낮추고 20초 이상은 10%를 지급한다. seconds=min(20,max(2,ceil(ms/1000))), 각 칸 점수=max(1,floor(기본배점×(100−(seconds−2)×5)/100)). 각 칸마다 정수 점수를 독립 계산해 누적한다. 2000ms와 2001ms는 다른 구간이며 3000ms는 3초, 3001ms는 4초 구간이다.

오답 1회당 −10점. 같은 칸 재시도는 시간을 초기화하지 않는다. 숫자 입력만으로는 점수를 주지 않고 정답 확인 시 지급한다. 총점 하한은 0이다. 정답이 아닌 재시도에 시간 점수를 중복 부여하지 않는다.

59×96의 입력 칸은 13개, 배점은 15/16이다.

## 호환성과 운영 준비

이전 세션에는 cellScoring이 없어 기존 시간 기준과 −30점을 유지한다. 저장된 점수를 재계산하지 않는다. 서버가 cellScoring 응답을 주지 않으면 클라이언트는 새 기준을 임의로 켜지 않는다. 새 서버 SQL은 cell_scoring 기본 false를 추가하고 새 시작 RPC에만 true를 저장한다. 새 순위는 새 기준의 기록만 비교하고 5/10문제를 계속 구분한다. tightTime 기준 순위에는 새 cellScoring 기록이 섞이지 않는다. 새로운 도전 ID를 이전 tightTime 시작으로 재사용하거나 이전 ID를 새 시작으로 전환하는 것은 거절한다.

구현 원본: supabase/vertical-cell-scoring.sql. 사용자 승인 후 실제 배포 도구가 반환한 버전 20261005070249로 운영 마이그레이션 파일을 저장했다. gugudan-api version 16 ACTIVE 재배포를 완료했다. 프론트엔드 정식 호스팅 배포는 별도다.
