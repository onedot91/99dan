# 출제 다양성과 0 빈도 검증

2026-10-03. 요청: 위의 수·곱하는 수 빈칸 추가, 곱하는 수의 일의 자리 0 빈도 감소. 앞선 66×0 계산 순서의 강조 혼동도 수정했다. 사용자 승인 후 운영 SQL/API 반영과 검증을 완료했다.

## 변경

- 새 세트의 b%10=0 문제는 최대 1개. 약 25%의 세트에서만 포함: 전체 문항 기준 5문제 약 5%, 10문제 약 2.5%.
- 기존 下·中·上 올림 비중과 중복 없는 숫자 구성은 유지하고 출제 순서를 섞음.
- 中 3/上 5 빈칸 문항, 각 2/3칸 유지. 유형은 기존 부분곱·합, 위의 수, 곱하는 수의 일/십의 자리. 上에는 네 유형이 모두 들어가고 中에는 서로 다른 세 유형이 들어감.
- 피연산자 빈칸은 한 칸만 허용. 위의 수는 완성된 십의 자리 부분곱, 곱하는 수 일의 자리는 완성된 일의 자리 부분곱, 곱하는 수 십의 자리는 완성된 십의 자리 부분곱으로 유일하게 추론 가능.
- 피연산자 빈칸을 접근성 이름에 정답 숫자로 노출하지 않음. 오답·역순 선택·칸별 시간·정답 점수·중복 금지 유지.
- 66×90은 첫 단계 `66 × 0`으로 두 6과 곱하는 0을 강조. 다음 자리 맞춤 0에는 피연산자 강조 없음. 그 뒤 6×9 강조.
- 새 API 옵션 puzzleOperands는 puzzles와 manualZero를 요구. 이전 운영 API는 새 옵션을 무시하고 기존 응답을 반환해 호환. 새 SQL은 기존 함수 두 개를 추가하고 기존 칸 매핑 함수를 확장하며, 기존 기록이나 테이블을 변경하지 않음.

## 실제 화면

실제 VerticalPlay/Progress와 useVerticalGame을 사용하는 QA 진입점, 가상 학생 999 로컬 저장소만 사용. 운영 서버에 풀이를 저장하지 않음.

- 上 첫 문제: 4□ × 21, 부분곱 4□/940, 최종 답 98□. 위의 수 빈칸 오답 1은 유지, 마지막 합의 7을 먼저 맞힘 → 위의 수 7 → 부분곱 7, 정답 모션 및 자동 다음 문제 확인. 점수 36→102→169.
- 둘째 문제: 64 × 3□, 부분곱 512/19□0, 합 243□. 부분곱 2를 먼저 입력 → 곱하는 수 8 → 합 2, 자동 전환 확인. 누적 368점.
- 셋째 문제 320×568: 39 × □2, 완성된 부분곱 3510으로 곱하는 수 십의 자리 추론. 세 빈칸 모두 68×50.4px, 행 안에 배치, 가로 넘침 없음.
- 66×90 첫 화면 source-digit는 6·6·0. 첫 0 제출 후 다음 줄 자리 맞춤 0의 source-digit는 없음. 두 번째 0 제출 뒤 6×9로 이동, 20→40점 확인.
