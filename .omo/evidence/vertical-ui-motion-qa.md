# 두 자리수 곱셈 UI·모션 검증

2026-10-03, localhost 개발 서버의 예비 번호로 검사했다. 운영 학생 기록이나 서버 설정은 변경하지 않았다.

## 변경
- 기존 픽셀 토큰·Galmuri·NumberPad를 재사용했다. 새 의존성은 없다.
- 네 자리 열, 고정 올림 행, 판 높이에 맞춘 글자 크기와 키패드 배치로 빈 공간을 정리했다.
- 현재 칸 등장, 올림 상승, 칸 확정·작은 파편, 실제 점수 증감, 반복 오답 흔들림, 완료 체크 도장, 800ms 자동 전환을 연결했다.
- 완료 시 키패드를 제거하지 않아 판·키패드의 위치와 크기가 동일했다.
- 최종 결과의 점수·다섯 식·명예의 전당·재시작을 데스크톱 두 열/모바일 한 열로 정리했다.

## 관찰
- 320×568, 375×667, 390×844, 768×650, 1280×650, 844×390에서 실제 풀이 화면을 검사했다. 가로 넘침 없이 키패드 12개가 화면 안에 있으며 최소 터치 크기는 44px이었다.
- 53×72의 곱셈 올림 2는 백의 자리 위에 40px 칸과 약 29px 숫자로 표시됐다.
- 42×24의 덧셈 올림은 부분곱 위 백의 자리에 표시됐다. 덧셈 중 곱셈 기호는 rgb(28,22,56), 자동 0은 rgb(128,128,128)이었다.
- 숫자/Enter/Backspace 입력, 같은 칸의 연속 오답, 칸별 실제 점수 증감과 하한 0점을 검사했다. 정답은 입력만으로 득점하지 않고 확인할 때 확정된다.
- 다섯 문제를 끝까지 풀어 최종 939점을 확인했다. 두 오답과 칸별 시간 차감이 반영됐고 완료 화면에 다섯 식이 나타났다.
- 결과 버튼은 320×568, 375×667, 390×844에서 화면 안에 표시됐다. 짧은 화면에서는 장식 트로피를 숨겨 공간을 확보한다.
- 점수 DOM 중복을 유발한 sibling key 충돌을 수정했다. 수정 이후 완주까지 브라우저 warn/error는 없었다.
- 트로피의 opacity 등장 효과에서 SVG가 사라지는 렌더링을 발견해 transform만 사용하는 등장으로 수정했고 실제 표시를 확인했다.
- reduced motion은 CSS 경로를 검토했다. OS 설정 전환과 실제 학교 기기·보조기술 검증은 수행하지 않았다.

## 자동 검증
- `npm run build`: 통과, 80 modules.
- `node --experimental-strip-types --test tests/*.test.mjs`: 30/30 통과.
- 신규 feedback 테스트는 실제 득점 차이, 시간 차감·올림, 오답 재시도, 하한 0, 다음 문제 이전 효과 제거와 마지막 칸 중복 득점 방지를 검증한다.
