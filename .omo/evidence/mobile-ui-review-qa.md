# 모바일 UI 재검토

2026-10-03. 사용자 요청: 모바일 UI 재검토, 가로선 아래 숫자 간격 축소.

## 수정

- src/vertical.css: 가로선 아래 덧셈 올림 예약 공간을 44px에서 8px로 축소. 실제 덧셈 올림이 필요한 단계에만 44px 확보. 정답 입자가 종이 밖으로 나가 짧은 가로 화면에 스크롤을 만드는 문제는 overflow:clip으로 방지.
- src/mobile.css: 560~700px 너비, 450px 이하 높이에서 식과 숫자 패드를 좌우 배치. 568×320에서도 표시되도록 숫자 행 최소 높이 및 올림 행을 조정. 덧셈 올림 입력 공간은 40px 유지.
- src/hall.css: 좁은 화면에서 긴 점수가 전체 순위를 가로로 늘리는 문제 수정. 400px 이하에서는 번호와 점수를 두 줄로 배치.
- src/teacher.css: 320px 교사 화면에서 최고 점수 123,456을 한 줄로 표시.
- tests/mobile-ui-preview.*: 실제 홈·교사·순위·번호·완료 컴포넌트와 가상 API 응답으로 재검증 가능. 운영 서버 요청을 보내지 않음. tests/vertical-puzzle-preview.tsx는 실제 헤더 크기와 99×99 올림 사례 추가.

## 실제 브라우저 검증

CUA의 실제 Chromium 브라우저. 사용자 원래 탭의 기록과 설정은 변경하지 않음. 풀이 저장소는 가상 번호 999/998만 사용. 교사 설정 변경은 메모리의 가상 데이터에만 적용.

- 홈·순위·교사·번호·완료: 320×568, 360×640, 390×844, 430×932, 667×375, 844×390의 30개 화면에서 가로 넘침 없음.
- 실제 두 자리 수 풀이: 위 크기와 568×320에서 식·모든 패드 버튼이 화면 안에 표시. 빈칸·패드 높이 최소 44px.
- 320px 홈에서 10문제를 선택하면 도전 시작 문구와 선택 표시 변경.
- 320px 교사 화면: 난이도 변경 시 자동 저장과 배지 변경, 추천 이유 펼치기. 최고 점수 폰트 14px, 한 줄 높이 19px, 넘침 없음.
- 순위: 구구단의 123,456점과 두 자리 수의 2,000점, 두 자리 번호·나 표시 포함. 종류 탭 전환과 5/10문제 탭 표시 확인.
- 학생 번호 23번 확인 창, 교사 입력 창 확인. 320×350 높이에서 교사 창과 입력·취소·진입 버튼이 화면 안에 표시. 실제 모바일 키보드는 에뮬레이션하지 않았고 가용 높이만 축소함.
- 47×21의 합 빈칸 먼저 선택 → 오답 1 → 정답 7 → 위의 수 7 → 부분곱 7. 오답 coral/aria-invalid 표시, 점수 35→102→169, 정답 모션 이후 두 번째 64×38로 자동 전환.
- 66×90: 0→자리 맞춤 0→4 입력 후 곱셈 올림 칸 표시. 가로선 다음 예약 행은 8px. 320px 올림 글자 24px, 버튼 68×44px.
- 99×99: 부분곱과 합의 일·십 자리 입력 후 덧셈 올림 칸 표시. 세로는 예약 행 44px, 568×320 가로는 40px. 입자 효과가 있어도 문서 크기 568×320, 가로·세로 넘침 없음.
- 검증 화면 console warn/error 없음.

## 증거와 검증 결과

- npm run build 통과, 80 modules.
- QA 진입점 두 개의 strict TypeScript 검사 통과. 첫 별도 검사 명령은 allowImportingTsExtensions 옵션 누락으로 실패했으며 프로젝트와 같은 옵션으로 재실행해 통과.
- git diff --check 통과. CSS·QA 진입점 변경이므로 채점 로직 테스트와 운영 SQL 검증은 반복하지 않음.
- 사용자가 설치를 거절한 LSP는 사용하지 않았고 새 의존성 없음.
- 실제 iOS Safari/Android 기기, 손가락 터치 및 모바일 키보드 검증은 미실시. 프론트엔드 운영 배포는 이 작업에 포함하지 않음.
