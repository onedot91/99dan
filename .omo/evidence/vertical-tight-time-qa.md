# 칸별 시간 점수 비중 확대

2026-10-05. 사용자 승인 후 운영 반영 완료. 기본 200점/문제와 오답 −30점, 난이도 통합, 5/10문제 순위 구분은 유지한다.

## 최종 기준

각 칸이 활성화된 때부터 정답 확인까지 밀리초로 측정한다. 오답 재시도는 시간을 초기화하지 않는다. 빈칸 문항의 선택 변경은 기존 방식대로 해당 칸에 사용한 시간을 누적한다.

각 정답 칸의 시간 기여값은 `min(max(ms − 2000, 0), 18000)`이다. 문제의 시간 감점은 `floor(기여값 합계 × 60 / (18000 × 입력 칸 수))`이다. 실제 각 칸에 별도로 상한을 적용하므로 한 칸에서 오래 머물러도 다른 칸의 시간 점수를 소진하지 않는다. 진행 중에도 정답 확인 직후 감점을 반영한다.

모든 칸을 같은 시간에 맞힌 문제의 점수: 2초 이하 200, 3초 197, 4초 194, 5초 190, 6초 187, 8초 180, 10초 174, 12초 167, 15초 157, 20초 이상 140. 중간 시간도 연속 계산하며 화면 점수는 정수다. 제한 시간과 시간 초과 종료는 없다.

## 호환성과 운영 반영

새 시작 요청과 응답의 `tightTime:true`로 기준을 합의한다. 서버가 새 응답을 보내지 않으면 기존 규칙을 사용해 화면과 서버 점수의 불일치를 방지한다. 로컬/예비 번호와 검증용 화면은 새 기준을 사용한다.

`supabase/vertical-tight-time.sql`은 운영 migration `20261005062629_gugudan_vertical_tight_time`의 원본이다. 적용된 DB에 다시 실행하지 않는다. 새 `tight_time`은 기본 false로 기존 기록의 점수·시간 기준을 보존한다. 새 시작 RPC는 새 기록에만 true를 저장하고, 기존 ID를 새 규칙으로 전환하지 않는다. 완료 재전송은 저장된 점수를 반환한다. 새 순위 RPC는 새 기준의 기록만 비교하며 이전 기록은 삭제하지 않는다.

사용자 승인 후 SQL 적용 → Edge API version 15 재배포를 완료했다. 실제 배포 도구가 반환한 migration 버전으로 파일을 저장했다. 이전 학생 앱의 시작과 순위 요청은 기존 경로를 유지한다. 새 함수는 security invoker/search_path=''이고 PUBLIC/anon/authenticated 실행 권한을 취소한다. 운영 검증 상세는 `vertical-tight-time-deployment-qa.md`에 기록했다. 프론트엔드 정식 호스팅 배포는 별도다.
